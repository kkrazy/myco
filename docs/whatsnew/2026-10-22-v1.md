# 平台接入 + 模型切换大更新

本次更新带来了多个平台接入方式和更灵活的模型切换能力，以下是本次上新的功能速览。

## 🔄 `/model` — 模型网关切换

- 直接输入 `/model` 打开选择器，查看并切换当前可用的模型网关。
- `/model gw:<名称>` 激活指定的网关配置；`/model gw:default` 恢复系统默认。
- 每个会话可以独立选择不同的网关，互不影响。

## 📋 `/fr ` — 快速功能请求

- 在聊天里直接用 `/fr <描述>` 提交功能请求，请求会记录到 Plan 面板。
- 支持投票、评论，重要需求会被排进任务队列。

## 🤖 `/run-n2` — N2 模式任务派发

- 用 `/run-n2 <任务描述>` 以 N2 模式派发任务，主会话模式不受影响。
- 适合并行推进独立子任务，任务状态可在 Plan 面板实时查看。

## 🧠 RLM 会话支持

- 通过 `/rlm session on` 为当前会话开启 RLM 模式（`/rlm session off` 关闭），侧边栏会话卡片显示 🧠 RLM 徽标。
- **更节约上下文**：上下文管理从"窗口 + 压缩"升级为 **REPL + 变量**——信息存放在运行环境的内存里，模型通过 `rlm_eval` 用变量按名读写，对话窗口中只保留变量引用而非全文，同样的上下文预算能承载远多于传统窗口压缩方案的工作量。
- 内核状态跨 turn 持久，支持快照 / 恢复；`rlm.spawn` 可编程方式派生子代理并行推进任务，子代理深度受运行时上限（depth 1 / maxDepth 3）约束。
- 支持声明式 DAG 编排：`rlm.runFactory(spec)` 按依赖分波调度（上限 MAX_NODES=1024 / MAX_RETRIES=10 / MAX_PARALLEL=64），可选 fail_fast / continue / escalate 失败策略。
- RLM 会话走独立的提示词与运行链路；非 RLM 团队完全不受影响（字节级不变）。

## working工作目录展示

- 侧边栏每个会话卡片新增**实时状态徽标**，一眼看出"哪个会话正在干活"：
  - Claude 正在执行任务时显示 `● working`（脉冲动画），任务完成切换为 `◦ to review`。
  - 打开会话即自动清除"待查看"；新一轮任务开始时"working"优先显示。
- 会话的工作目录（workspace 路径）随会话卡片一并展示，多会话并行时可直接分辨每个会话在操作哪份代码。

## 🔗 delm / codehub / 自带 Claude Code 接入

- 现在支持 **delm**、**codehub** 平台账号接入。
- 也支持使用你**自己的 Claude Code**（本地 CLI）作为执行引擎。
- 在 Config 面板中配置对应网关（如 `ANTHROPIC_BASE_URL` / `ANTHROPIC_MODEL`）即可启用。
