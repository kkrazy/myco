# 平台接入 + 模型切换 + Harness² 自动调优大更新

本次更新带来了多个平台接入方式、更灵活的模型切换能力与全新的**主题切换**，并新增 **Harness²（harness 自动调优）** 与 **N 路径并行探索（/run-explore）** 能力。以下是本次上新的功能速览。

## 🧭 `/run-explore` — N 路径并行探索（算法设计难题专用）

`/run-n2` 的双 agent 模式下，两个 worker 往往收敛到同一条解法思路上。对于**难的算法设计类题目**，`/run-explore [N] <任务>`（默认 N=4，可指定 2..512）拉起 N 个并行 explorer（`path-1` … `path-N`），**每个 explorer 深挖一条候选解法路径**——不同的算法族 / 表示方式 / 架构方向，用实测证据说话，最后收敛到最优方案。

### 去中心化协作（复用 Delm board 协议）

- **无中央控制器**：协调只通过共享 board（与 run-n2 同一套 queue / claim / FACT / FAIL 语义）。`path-1` 作为"路径播种者"分析任务后发布最多 N 条互不重叠的候选方向；其余 explorer 各 claim 一条深挖。
- **量化优先纪律**：每条路径的第一个里程碑是**最小可测基准**（在真实输入上测量该方向的核心 trade-off——吞吐 / 压缩比 / 时延 / 复杂度）。方向被判死路必须**带着测量数据**以 done + FAIL note 关闭，绝不凭直觉放弃。
- **跨路径学习**：peer 的 FACT note 对所有路径生效（如"LZ4 单遍下压缩比与 GBps 互斥，实测见附件"）——一条路径测出的硬边界可以直接救活其它路径的探索预算。
- **收敛集成**：当 board 显示所有路径均已 done 且无 open item，第一个察觉的 explorer reserve 一个集成 item，产出最终 SOLUTION 对比文档——按实测数据选出最优（或最优杂交）方案，并说明落选路径为何落选。

### 自演进（共享 Continual Harness）

- explorer 强制运行 **RLM 引擎**，并共享一个 **per-task 的自演进规则存储**（`explore-task-<任务指纹>`）。
- 任何 explorer 通过 `rlm.addPrompt(规则, 证据)` 写入的规则，会组合进**所有 worker** 的提示词，并且**跨 run 累积**——同一道难题第二次 `/run-explore` 时，团队自动带着上次学到的全部经验开工，越跑越强。
- 活动中的学习走 board FACT/FAIL note（即时传递），跨 respawn / 跨 run 的学习走共享 harness（持久传递）——两层自演进互补。

### 使用与产物

```text
/run-explore 设计一个压缩算法：压缩比损失<5% 且吞吐>1GBps     # 默认 4 路并行
/run-explore 6 用 suffix-array 思路解决该匹配问题             # 指定 6 路
```

- 进度实时滚动到聊天面板（每条路径的 claim 状态在看板面板可见）；Stop 按钮、多 lane 看板、断线重连行为与 `/run-n2` 一致。
- 运行结束自动生成**逐路径证据报告**写入 `_myco_/explore/`：每条路径的结局（✅ done 摘要 / ❌ FAIL 证据）、每路径工具调用量、整体队列收束情况。
- 完全**增量式**：单 agent、`/run-n2`、`/compare`、`/run-experts` 的既有行为字节级不变；explore worker 走 RLM 是该 lane 自己的决策，不影响会话级 RLM 开关。

## 🔄 `/model` — 模型网关切换

- 直接输入 `/model` 打开选择器，查看并切换当前可用的模型网关。
- `/model gw:<名称>` 激活指定的网关配置；`/model gw:default` 恢复系统默认。
- 每个会话可以独立选择不同的网关，互不影响。

## 📋 `/fr ` — 快速功能请求

- 在聊天里直接用 `/fr <描述>` 提交功能请求，请求会记录到 Plan 面板。
- 支持投票、评论，重要需求会被排进任务队列。

## 🤖 `/run-n2` — N2 模式任务派发

- 用 `/run-n2 <任务描述>` 以 N2 模式派发任务，主会话模式不受影响。
- 适合并行推进独立子任务，任务状态可在 Plan 面板实时查看。

## 🧠 RLM 会话支持

- 通过 `/rlm session on` 为当前会话开启 RLM 模式（`/rlm session off` 关闭），侧边栏会话卡片显示 🧠 RLM 徽标。
- **更节约上下文**：上下文管理从"窗口 + 压缩"升级为 **REPL + 变量**——信息存放在运行环境的内存里，模型通过 `rlm_eval` 用变量按名读写，对话窗口中只保留变量引用而非全文，同样的上下文预算能承载远多于传统窗口压缩方案的工作量。
- 内核状态跨 turn 持久，支持快照 / 恢复；`rlm.spawn` 可编程方式派生子代理并行推进任务，子代理深度受运行时上限（depth 1 / maxDepth 3）约束。
- 支持声明式 DAG 编排：`rlm.runFactory(spec)` 按依赖分波调度（上限 MAX_NODES=1024 / MAX_RETRIES=10 / MAX_PARALLEL=64），可选 fail_fast / continue / escalate 失败策略。
- RLM 会话走独立的提示词与运行链路；非 RLM 团队完全不受影响（字节级不变）。

## 🎯 Harness² 自动调优

一套全新的 **harness 配置自动调优**能力：给它一个具体的代码任务，它会自动生成多个 harness 配置变体，跑真实 rollout，盲选出最优配置，供你采纳或发布。

### `/harness run` — 启动调优

- 直接输入 `/harness run <任务描述>` 启动一次调优（sweep）：系统会围绕你的任务自动生成 N 个 harness 变体（inv / dom / agg），每个变体跑真实 rollout，最后**盲选**出表现最优的配置——只看结果、不看 harness 内容，避免主观偏好。
- 可选参数可组合：
  | 参数 | 说明 | 示例 |
  |---|---|---|
  | `--k <1-4>` | 每个变体的 rollout 轮数，默认 1，每加一轮花费翻倍 | `/harness run --k 2 <task>` |
  | `--n2` | 用双 agent 协作模式（run-n2）跑 rollout | `/harness run --n2 <task>` |

- k=1 单 agent 约 5 分钟即可完成一轮；任务文本直接传给 adapter，**任何项目目录都能用**（不需要 `_myco_/plan.json`）。

### 调优生命周期：run → diff → adopt → rollback

- `/harness run` 启动 sweep，`/harness status [id]` 查看进度，`/harness cancel` 随时取消。
- sweep 完成后用 `/harness diff [id]` 查看改动内容，确认无误后 `/harness adopt [id]` 把选中的 harness 写进当前会话工作区——**下一轮对话立即生效**。
- 不满意随时 `/harness rollback [sweepId]` 回滚。

### `/harness init` + `/harness install` — 模板与本地安装

- `/harness init` 在工作区生成 `_harness_/template/`（`systemprompt.md`、`tool_guidance.md`、`guardrails.md`）作为自定义起点。
- `/harness init n2` 额外生成三个 n2 组件：`worker_a_startup.md`、`worker_b_startup.md`、`board_guidance.md`。
- `/harness install <目录>` 可从本地目录把一份 harness 安装进当前会话（支持相对 / 绝对路径）。

### Harness 市场 — 发布与复用

- 打开 **Skills 面板 → Harness 市场** 标签即可浏览、查看详情、安装别人发布的 harness。
- 命令行也可操作：`/harness publish [id]` 把 sweep 结果发布到市场；`/harness-market list` / `info <name>` / `install <name>` 浏览与安装。
- **跨项目复用（P8）**：安装过市场 harness 的会话，下次 `/harness run` 会自动以它为调优的起始基线（`HARNESS2_MYCO_BASE_HARNESS`），而不是从零开始。

### run-n2 协作调优

- `/harness run --n2 <task>` 在 **worker-A + worker-B 共享一块 DelmBoard** 的双 agent 协作模式下跑 rollout，Harness² 会自动调优协作策略。
- n2 专属的三个组件（worker-A 任务分解、worker-B 环境探索、协作板规范）不是写盘文件，而是在 TeamSession 启动时直接注入到 worker 系统提示词里。

### 组件是如何映射到 myco 的

采纳 / 安装时，harness² 的布局会映射到 myco 真实路径：

| harness² 路径 | myco 路径 |
|---|---|
| `systemprompt.md` | `CLAUDE.md` |
| `guardrails.md` | `CLAUDE.md`（追加） |
| `tool_guidance.md` | `.claude/tool_guidance.md` |
| `sub_agents/<name>/AGENT.md` | `.claude/agents/<name>.md` |
| `skills/<name>/` | `.claude/skills/<name>/` |
| `scripts/<name>.py` | `.myco_harness/scripts/<name>.py` |

> 提案阶段走 myco 新增的 `claude_local` 通道（保留调用方 `ANTHROPIC_*` 环境变量，复用 mycod 已配置的网关），不需要额外账户。
